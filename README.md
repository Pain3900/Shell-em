# Эмулятор командной оболочки UNIX (вариант 15)

Практическая работа №1 по дисциплине «Конфигурационное управление».
Консольное приложение (CLI) на Python, имитирующее работу командной
строки UNIX-подобной ОС. Файловая система эмулятора — виртуальная (VFS),
загружается из JSON-файла и полностью хранится в памяти.

## Содержание

1. Сборка и запуск
2. Структура проекта
3. Этап 1. REPL
4. Этап 2. Конфигурация
5. Этап 3. VFS
6. Этап 4. Основные команды
7. Сводная таблица команд

## 1. Сборка и запуск

Требуется Python 3.8+, сторонние библиотеки не нужны.

```sh
sh run.sh [--vfs ПУТЬ] [--script ПУТЬ]    # Linux / macOS
run.bat [--vfs ПУТЬ] [--script ПУТЬ]      # Windows
```

Запуск тестов:

```sh
sh test.sh        # Linux / macOS
test.bat          # Windows
```

## 2. Структура проекта

```
src/shell_emulator/
    __main__.py   точка входа, параметры командной строки
    shell.py      класс Shell: приглашение, цикл REPL, стартовый скрипт
    parse.py      разбор строки на аргументы с учётом кавычек
    commands.py   встроенные команды
    vfs.py        виртуальная файловая система
tests/            модульные тесты (unittest)
scripts/          стартовые скрипты эмулятора и скрипты ОС для проверки
vfs/              примеры VFS в формате JSON
run.sh, run.bat   запуск эмулятора
test.sh, test.bat запуск тестов
```

## 3. Этап 1. REPL

Минимальный прототип: диалог с пользователем, команды `ls` и `cd` на
этом этапе — заглушки (выводят своё имя и аргументы), команда `exit`
завершает работу.

### Приглашение к вводу

Строится по реальным данным ОС: `user@host:путь$ `, где `user` — имя
пользователя ОС (`getpass`), `host` — имя компьютера до первой точки
(`socket.gethostname`). Начиная с этапа 4, `путь` — текущий каталог
VFS.

### Парсер

Разбивает введённую строку на аргументы с учётом кавычек:

| Ввод                  | Результат                  |
|-----------------------|----------------------------|
| `ls  -l   /tmp`       | `['ls', '-l', '/tmp']`     |
| `cd "My Documents"`   | `['cd', 'My Documents']`   |
| `ls 'a "b" \c'`       | `['ls', 'a "b" \\c']`      |
| `ls a"b c"d`          | `['ls', 'ab cd']`          |
| `ls ""`               | `['ls', '']`               |
| `cd My\ Dir`          | `['cd', 'My Dir']`         |
| `ls "abc`             | ошибка: кавычка не закрыта |

Правила: в одинарных кавычках всё берётся буквально; в двойных кавычках
`\` экранирует только `"` и `\`; вне кавычек `\` экранирует любой
символ.

### Обработка ошибок

| Ввод | Сообщение |
|------|-----------|
| `foo` | `shell: foo: command not found` |
| `ls "abc` | `shell: syntax error: unexpected EOF while looking for matching "` |
| `exit abc` | `shell: exit: abc: numeric argument required` |
| `exit 1 2` | `shell: exit: too many arguments` |

`Ctrl+D` завершает работу, `Ctrl+C` сбрасывает текущий ввод, стрелки
листают историю команд.

## 4. Этап 2. Конфигурация

### Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs ПУТЬ` | путь к физическому расположению VFS (JSON-файл) |
| `--script ПУТЬ` | путь к стартовому скрипту |

При запуске все параметры выводятся для отладки; не заданный параметр
выводится как `(not set)`:

```
$ sh run.sh --vfs vfs/deep.json --script scripts/start_ok.txt
[debug] vfs=vfs/deep.json
[debug] script=scripts/start_ok.txt
```

### Команда conf-dump

Выводит параметры эмулятора в формате `ключ=значение`:

```
student@laptop:/$ conf-dump
vfs=vfs/deep.json
script=scripts/start_ok.txt
```

### Стартовый скрипт

Текстовый файл, по одной команде эмулятора в строке, пустые строки
пропускаются. Каждая команда печатается вместе с приглашением, затем её
вывод — как будто команды вводит пользователь. На первой ошибке
выполнение скрипта останавливается с сообщением
`script: error at line N, stopped`, после чего эмулятор переходит
в интерактивный режим. Команда `exit` в скрипте завершает эмулятор.

### Скрипты для проверки

| Файл | Что проверяет |
|------|---------------|
| `scripts/start_ok.txt` | стартовый скрипт без ошибок |
| `scripts/start_error.txt` | стартовый скрипт с ошибкой в 3-й строке |
| `scripts/test_ok.sh` | `--vfs` и `--script` с корректным скриптом |
| `scripts/test_error.sh` | остановка скрипта на первой ошибке |
| `scripts/test_params.sh` | без параметров, только `--vfs`, несуществующий скрипт, неизвестный параметр |

Скрипты ОС запускаются из корня проекта, например
`sh scripts/test_ok.sh`.

## 5. Этап 3. VFS

- VFS загружается из JSON-файла целиком в память; исходный файл только
  читается и никогда не изменяется.
- Содержимое файлов хранится в base64, поэтому поддерживаются и
  двоичные данные.
- При старте выводится сообщение из файла `motd`, если он есть в корне
  VFS.
- При ошибке загрузки VFS эмулятор сообщает причину и завершается
  с кодом 1.
- Без параметра `--vfs` эмулятор работает с пустой VFS (только корень
  `/`).

### Формат VFS

Корень — каталог. Каталог: `{"type": "dir", "children": {...}}`, где
`children` — словарь «имя → узел». Файл:
`{"type": "file", "data": "<base64>"}`. У любого узла можно указать
права доступа `"mode": "755"` (восьмеричная запись); по умолчанию
каталоги имеют права `755`, файлы — `644`.

```json
{
  "type": "dir",
  "children": {
    "motd": {"type": "file", "data": "SGVsbG8hCg=="},
    "home": {"type": "dir", "children": {}}
  }
}
```

После загрузки выводится размер VFS:

```
[debug] vfs loaded: dirs=8, files=6, levels=6
```

### Примеры VFS

| Файл | Содержимое |
|------|------------|
| `vfs/minimal.json` | пустой корневой каталог, без motd |
| `vfs/files.json` | несколько файлов в корне: motd, текстовые и двоичный |
| `vfs/deep.json` | вложенные каталоги, 6 уровней, motd |
| `vfs/broken.json` | некорректный JSON |
| `vfs/bad_type.json` | неизвестный тип узла |
| `vfs/bad_base64.json` | данные файла не в base64 |

Структура `vfs/deep.json`, на которой построены примеры этапа 4:

```
/
├── motd
├── etc/
│   └── config.txt
├── home/
│   └── user/
│       ├── docs/
│       │   ├── old/
│       │   │   └── draft.txt
│       │   └── report.txt
│       └── photo.bin
└── var/
    └── log/
        └── system.log
```

### Скрипты для проверки

| Файл | Что проверяет |
|------|---------------|
| `scripts/start_vfs.txt` | все команды этапов 1–3 |
| `scripts/test_vfs_minimal.sh` | минимальная VFS |
| `scripts/test_vfs_files.sh` | VFS с несколькими файлами и motd |
| `scripts/test_vfs_deep.sh` | VFS с вложенностью 6 уровней |
| `scripts/test_vfs_errors.sh` | ошибки загрузки VFS |

## 6. Этап 4. Основные команды

Команды `ls` и `cd` работают с VFS, добавлены команды `head` и `clear`.
Пути можно указывать абсолютные (`/home/user`) и относительные
(`docs`, `..`, `.`).

### ls [-l] [ПУТЬ]

Выводит содержимое каталога (по умолчанию текущего), по одному имени
в строке, в алфавитном порядке; к именам каталогов добавляется `/`.
Если путь указывает на файл, выводится имя файла. С ключом `-l`
перед именем выводятся права доступа.

```
student@laptop:/$ ls
etc/
home/
motd
var/
student@laptop:/$ ls -l home/user
drwxr-xr-x docs/
-rw-r--r-- photo.bin
```

### cd [ПУТЬ]

Переходит в каталог; без аргумента — в корень `/`. Текущий каталог
отображается в приглашении.

```
student@laptop:/$ cd home/user/docs
student@laptop:/home/user/docs$ cd ..
student@laptop:/home/user$
```

### head [-n ЧИСЛО] ФАЙЛ

Выводит первые строки файла, по умолчанию 10.

```
student@laptop:/$ head -n 1 /var/log/system.log
system started
```

### clear

Очищает экран терминала.

### Обработка ошибок

| Ввод | Сообщение |
|------|-----------|
| `ls nowhere` | `shell: ls: nowhere: No such file or directory` |
| `ls -x` | `shell: ls: invalid option -- 'x'` |
| `cd motd` | `shell: cd: motd: Not a directory` |
| `cd nowhere` | `shell: cd: nowhere: No such file or directory` |
| `cd a b` | `shell: cd: too many arguments` |
| `head` | `shell: head: missing file operand` |
| `head /home` | `shell: head: /home: Is a directory` |
| `head -n abc motd` | `shell: head: invalid number of lines: 'abc'` |

### Скрипты для проверки

| Файл | Что проверяет |
|------|---------------|
| `scripts/start_stage4.txt` | стартовый скрипт: все режимы `ls`, `cd`, `head`, `clear` |
| `scripts/stage4_errors.txt` | все ошибки команд этапа 4 |
| `scripts/test_stage4.sh` | запуск эмулятора с `vfs/deep.json`: сначала стартовый скрипт, затем ошибки из `stage4_errors.txt` на обычный ввод |

Стартовый скрипт останавливается на первой ошибке (требование этапа 2),
поэтому ошибки подаются эмулятору на обычный ввод: в интерактивном
режиме после ошибки работа продолжается. Если ввод идёт не с
клавиатуры, эмулятор печатает каждую введённую команду после
приглашения, и вывод выглядит как диалог.
