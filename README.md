# Эмулятор командной оболочки UNIX (вариант 15)

Практическая работа №1 по дисциплине «Конфигурационное управление».
Консольное приложение (CLI) на Python, имитирующее работу командной
строки UNIX-подобной ОС.

## Общее описание

**Этап 1. REPL** — минимальный прототип оболочки:

- Приглашение к вводу строится по реальным данным ОС:
  `username@hostname:~$`.
- Парсер корректно обрабатывает аргументы в кавычках.
- Команды `ls` и `cd` — заглушки: выводят своё имя и аргументы.
- Команда `exit` завершает работу эмулятора.

**Этап 2. Конфигурация** — эмулятор настраивается параметрами
командной строки:

- `--vfs ПУТЬ` — путь к физическому расположению VFS;
- `--script ПУТЬ` — путь к стартовому скрипту;
- при запуске выводятся все параметры (отладочный вывод `[debug]`);
- служебная команда `conf-dump` выводит параметры в формате
  `ключ=значение`.

**Этап 3. VFS** — подключена виртуальная файловая система:

- VFS загружается из JSON-файла целиком в память, исходный файл
  только читается и не изменяется;
- содержимое файлов хранится в base64, поэтому поддерживаются и
  двоичные данные;
- при старте выводится сообщение из файла `motd`, если он есть
  в корне VFS;
- при ошибке загрузки VFS эмулятор сообщает причину и завершается
  с кодом 1.

## Структура проекта

```
src/shell_emulator/
    __main__.py   точка входа (python -m shell_emulator)
    shell.py      класс Shell: приглашение, цикл REPL, выполнение строки
    parse.py      разбор строки на аргументы с учётом кавычек
    commands.py   встроенные команды (ls, cd, conf-dump, exit)
    vfs.py        загрузка VFS из JSON в память, motd
tests/            модульные тесты (unittest)
scripts/          стартовые скрипты эмулятора и скрипты ОС для проверки
vfs/              примеры VFS в формате JSON
run.sh, run.bat   запуск эмулятора
test.sh, test.bat запуск тестов
```

## Функции и настройки

### Приглашение

`user@host:cwd$ `, где `user` — имя пользователя ОС (`getpass`),
`host` — имя компьютера до первой точки (`socket.gethostname`),
`cwd` — текущий каталог (на этом этапе всегда `~`).

### Парсер (`parse.parse`)

| Ввод                  | Результат              |
|-----------------------|------------------------|
| `ls  -l   /tmp`       | `['ls', '-l', '/tmp']` |
| `cd "My Documents"`   | `['cd', 'My Documents']` |
| `ls 'a "b" \c'`       | `['ls', 'a "b" \\c']`  |
| `ls a"b c"d`          | `['ls', 'ab cd']`      |
| `ls ""`               | `['ls', '']`           |
| `cd My\ Dir`          | `['cd', 'My Dir']`     |
| `ls "abc`             | ошибка: кавычка не закрыта |

Правила: в одинарных кавычках всё буквально; в двойных кавычках `\`
экранирует только `"` и `\`; вне кавычек `\` экранирует любой символ.

### Команды

| Команда      | Описание |
|--------------|----------|
| `ls [арг…]`  | заглушка, выводит `ls: args=[...]` |
| `cd [арг…]`  | заглушка, выводит `cd: args=[...]` |
| `conf-dump`  | вывод параметров эмулятора `ключ=значение` |
| `exit [код]` | выход с кодом (по умолчанию 0) |

Ошибки: неизвестная команда (`command not found`), незакрытая кавычка
(`syntax error`), `exit abc` (`numeric argument required`),
`exit 1 2` (`too many arguments`). `Ctrl+D` завершает работу,
`Ctrl+C` сбрасывает текущий ввод, стрелки листают историю.

### Параметры командной строки

```
sh run.sh [--vfs ПУТЬ] [--script ПУТЬ]
```

Не заданный параметр выводится как `(not set)`. Пример запуска:

```
$ sh run.sh --vfs vfs/files.json --script scripts/start_ok.txt
[debug] vfs=vfs/files.json
[debug] script=scripts/start_ok.txt
```

### Формат VFS

Корень — каталог. Каталог: `{"type": "dir", "children": {...}}`,
где `children` — словарь «имя → узел». Файл:
`{"type": "file", "data": "<base64>"}`.

```json
{
  "type": "dir",
  "children": {
    "motd": {"type": "file", "data": "SGVsbG8hCg=="},
    "home": {"type": "dir", "children": {}}
  }
}
```

После загрузки выводится отладочная строка с размером VFS:

```
[debug] vfs loaded: dirs=8, files=6, levels=6
```

Примеры в папке `vfs/`:

| Файл | Содержимое |
|------|------------|
| `minimal.json` | пустой корневой каталог, без motd |
| `files.json` | несколько файлов в корне: motd, текстовые и двоичный |
| `deep.json` | вложенные каталоги, 6 уровней, motd |
| `broken.json` | некорректный JSON (для проверки ошибок) |
| `bad_type.json` | неизвестный тип узла (для проверки ошибок) |
| `bad_base64.json` | данные файла не в base64 (для проверки ошибок) |

### Стартовый скрипт

Текстовый файл, по одной команде эмулятора в строке, пустые строки
пропускаются. Каждая команда печатается вместе с приглашением, затем её
вывод — как будто команды вводит пользователь. На первой ошибке
выполнение скрипта останавливается с сообщением
`script: error at line N, stopped`, после чего эмулятор переходит
в интерактивный режим. Команда `exit` в скрипте завершает эмулятор.

### Скрипты для проверки (`scripts/`)

| Файл | Что проверяет |
|------|---------------|
| `start_ok.txt` | стартовый скрипт без ошибок, заканчивается `exit` |
| `start_error.txt` | стартовый скрипт с ошибкой в 3-й строке |
| `test_ok.sh` | `--vfs` и `--script` с корректным скриптом |
| `test_error.sh` | `--vfs` и `--script`, остановка на первой ошибке |
| `test_params.sh` | без параметров, только `--vfs`, несуществующий скрипт, неизвестный параметр |
| `start_vfs.txt` | все команды этапов 1–3, заканчивается ошибкой `exit 1 2` |
| `test_vfs_minimal.sh` | минимальная VFS со скриптом `start_vfs.txt` |
| `test_vfs_files.sh` | VFS с несколькими файлами и motd |
| `test_vfs_deep.sh` | VFS с вложенностью 6 уровней и motd |
| `test_vfs_errors.sh` | ошибки загрузки: нет файла, плохой JSON, неизвестный тип, не base64 |

Скрипты ОС запускаются из корня проекта: `sh scripts/test_ok.sh`.
Ввод эмулятора в них перенаправлен из `/dev/null`, чтобы после
стартового скрипта эмулятор не ждал ввода с клавиатуры.

## Сборка и запуск

Требуется Python 3.8+, сторонние библиотеки не нужны.

```sh
./run.sh          # Linux / macOS
run.bat           # Windows
```

Запуск тестов:

```sh
./test.sh         # Linux / macOS
test.bat          # Windows
```

## Пример использования

```
student@laptop:~$ ls -l "My Documents"
ls: args=['-l', 'My Documents']
student@laptop:~$ cd 'a b' c\ d
cd: args=['a b', 'c d']
student@laptop:~$ ls "unclosed
shell: syntax error: unexpected EOF while looking for matching "
student@laptop:~$ foo
shell: foo: command not found
student@laptop:~$ exit abc
shell: exit: abc: numeric argument required
student@laptop:~$ exit 7
```
